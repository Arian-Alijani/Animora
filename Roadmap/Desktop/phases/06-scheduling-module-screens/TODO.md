Seven decisions this list encodes, so the implementing sessions do not re-litigate them:

- **One calendar route serves day, week, month and the resource filter.** View mode, anchor date and
  resource filter are screen state on one route, not four near-identical screens — the same call
  phase 05 made for its one patient-list route (AG-14, DESK-ARCH-05, CONV-17).
- **Booking, rescheduling, cancelling and the status transitions are separate commands over one
  row.** ADR-0008 keeps the original `Appointment` id on a reschedule, so a reschedule is never a
  create; and one generic "save appointment" would let an illegal transition through, so each
  transition is its own command checked against the state machine in its handler
  (05-domain-model.md).
- **The DOM-08 overlap check runs in the handler, never in the validator.** It needs the other
  appointments on the same resource, which a field validator cannot see (SH-05) — so the handler
  asks the read seam and returns a `SchedulingErrors` code, mirroring `SavePatientHandler`'s
  owner-existence check, with server re-validation left as `TODO(P2)` (PHASE criterion 3).
- **Scheduling never references Clients.** The patient a booking is made for arrives through a
  `Mediator` request declared in the one assembly both modules already share, never a
  `Modules.Clients` project reference (DT-01, DIR-01, DIR-05); item 4 asks which shape that takes
  before anything depends on it.
- **Service types and grooming types stay two entities with one screen each.** The module catalog
  owns both separately (04-module-catalog.md); a generic "catalog kind" abstraction would fuse two
  entities the backend keeps apart (AG-14).
- **Only the sync-class declaration of the "add a synced entity" recipe is in scope.** Appointment is
  `StateMachine` per ADR-0008 and the three catalogs are `MutableLWW`; the SQLite mirror, the outbox
  transaction and the sync test matrix are phase 17 and P2 (DT-04, DT-12) — the same line phase 05
  drew.
- **`AppointmentSeries` and `ReminderRule` are out of this phase.** Recurrence is referenced by id
  and never embedded (05-domain-model.md), and reminder computation is phase 26 — this phase books
  single appointments only.
