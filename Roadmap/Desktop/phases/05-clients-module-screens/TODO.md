Five decisions this list encodes, so the implementing sessions do not re-litigate them:

- **One patient-list route serves both modes.** The owner-scoped list and the global list differ only
  by an optional owner filter arriving as the navigation parameter — one screen, one handler, one
  argument, instead of two near-identical screens (AG-14, DESK-ARCH-05, CONV-17).
- **The medical-file summary reads through the patient seam, not a seam of its own.** `MedicalFile` is
  inside the Patient aggregate (05-domain-model.md), so a separate `IMedicalFileReadStore` would split
  one aggregate across two interfaces for no gain (AG-14, INV-18).
- **The medical file's links out stay markers.** Visit history is Visits' screen (phase 07) and
  attachments are Files' (phase 08); the summary screen carries `TODO(P1-07)`/`TODO(P1-08)` where those
  navigations land rather than reaching into another module (DT-01, CM-06).
- **Only the sync-class declaration of the "add a synced entity" recipe is in scope.** `Animora.Contracts`
  can carry Owner/Patient/MedicalFile as `MutableLWW` with field groups now (SYNC-R-01/03); the SQLite
  mirror, outbox transaction and sync test matrix belong to phase 16 and P2 (DT-04, DT-12).
- **Read and write seams are split per aggregate**, as in phase 04, because Stage C binds the halves to
  different technologies (Dapper reads / EF Core writes, DT-05).
